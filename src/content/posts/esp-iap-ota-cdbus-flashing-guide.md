# ESP IAP、OTA 区别与 CDBUS 烧录说明

整理日期：2026-11-10

适用范围：公司现有 ESP 固件的 CDBUS 升级操作。模式编号依据公司当前使用经验记录；不同 CDBUS 工具版本应以实际界面和配套说明为准。地址和文件封装示例依据当前 `dp_esp` 工程，不代表公司所有 ESP 固件。

## 1. 操作结论

公司目前存在支持 IAP 升级和不支持 IAP 升级的 ESP 程序。通过 CDBUS 烧录蓝牙程序时，按以下顺序操作：

1. 优先使用 **IAP 模式 1**：先进入 BL，再烧录配套的 IAP HEX。
2. 如果无法完成 IAP，先检查连接、设备地址、波特率及进入 BL 的情况。
3. 对于支持应用侧 OTA 升级的程序，改用 **OTA 模式 4**：由正在运行的应用接收升级数据，不要求先进入 BL。
4. 等待工具报告完成、设备重启，并确认新固件版本及蓝牙功能。

**不支持 IAP，不等于一定支持 OTA。** 模式切换的前提是设备当前固件支持对应的升级协议，并且选择了匹配的升级文件。

## 2. 基本概念

### 2.1 ROM、BL 与 App

ESP 的典型启动顺序为：

```text
上电或复位 → 芯片 ROM 启动代码 → Flash 中的 BL → App 主程序
```

| 名称 | 含义 | 在升级中的作用 |
|---|---|---|
| ROM 启动代码 | 芯片出厂固化的启动代码 | 提供底层启动和 ROM 下载能力 |
| BL（bootloader） | Flash 中的引导程序 | 启动 App；项目自定义 BL 还可处理升级通信、校验和搬运 |
| App | 产品主程序 | 执行业务功能，也可接收升级数据 |

本文“进入 BL”指进入公司固件的自定义引导升级模式，**不等于进入 ESP 的 ROM 下载模式**。按 BOOT 键进入的下载模式通常用于乐鑫工具烧录，不能直接代替 CDBUS 所需的 BL 协议。

### 2.2 IAP 的含义

IAP 是 In-Application Programming，即设备利用自身软件完成 Flash 编程。在公司的操作语境中，IAP 特指：进入自定义 BL，由 BL 接收固件并写入主程序区。

```text
CDBUS 工具 → 通信链路 → 进入 BL → 擦除、写入主程序区 → 重启运行新 App
```

进入 BL 后，原 App 暂停运行，由 BL 负责升级。能否使用这条路径，取决于设备是否具有兼容的 BL、进入 BL 的机制以及正常的通信链路。

### 2.3 OTA 的含义

OTA 是 Over-The-Air，通常指通过无线链路传送固件，例如蓝牙或 Wi-Fi。它强调传输方式；IAP 强调设备自身编程能力，两者并不是严格互斥的技术。

公司的 CDBUS 操作中，“OTA 模式 4”按应用侧接收升级数据的流程理解：原 App 继续提供升级通信，不需要在传输前切入 BL。实际链路是否无线，应以工具连接拓扑为准，不能只根据“OTA”按钮名称判断。

“不进入 BL，直接在程序中升级”更准确的表述是：

> 不需要先手动进入 BL，由运行中的 App 接收并处理升级数据。新固件可能先写入暂存区，重启后再由 BL 校验、搬运或切换。

因此，“在程序中升级”不代表一边执行原主程序、一边直接覆盖它所在的 Flash 区域，也不代表整个升级过程完全不经过 BL。

## 3. IAP 与 OTA 对比

| 对比项 | 公司 IAP 流程 | 公司 OTA 流程 |
|---|---|---|
| CDBUS 模式 | 模式 1 | 模式 4 |
| 开始传输前 | 先进入 BL | App 保持运行，不要求先进入 BL |
| 谁接收固件 | 自定义 BL | 原 App 的升级服务 |
| 设备侧必要条件 | BL、进入 BL 机制和通信协议兼容 | App 能正常运行，并支持对应升级协议 |
| 当前工程写入位置 | 直接写入 App 区 | 先写入升级暂存区 |
| 当前工程生效方式 | 写完后启动 App | 重启后由 BL 校验并复制到 App 区 |
| 原 App 损坏时 | 若 BL 完好且可进入，可尝试恢复 | 通常无法通过原 App 接收固件 |
| 下载中断的影响 | App 区可能已经部分覆盖 | 暂存下载阶段通常尚未覆盖原 App |
| 是否自动回滚 | 取决于具体实现 | 取决于具体实现，不能仅凭 OTA 名称认定 |

两种方式最终都需要擦写 Flash 并运行新程序。可靠性由分区、校验、断电恢复及回滚机制决定，不能简单归结为“IAP 安全”或“OTA 安全”。

## 4. 当前 dp_esp 工程的文件区别

当前工程用同一个 `dp_esp.bin` 生成两种 HEX，它们的主程序内容相同，但目标地址和封装不同。

| 文件 | 目标地址 | 内容 | 对应用途 |
|---|---|---|---|
| `dp_esp_iap.hex` | `0x10000` | 主程序内容 | 配套 IAP 流程 |
| `dp_esp_ota.hex` | `0x187000` | 4 字节升级头 + 主程序 + 2 字节 CRC | 配套 OTA 流程 |

当前 OTA 的设备侧流程为：

```text
App 接收固件 → 写入 0x187000 暂存区 → 重启
    → BL 检查标记、长度及 CRC
    → 擦除 0x10000 主程序区
    → 复制新程序并校验
    → 清除暂存标记 → 运行新程序
```

这是“暂存后复制覆盖”的实现，不是 A/B 双应用分区切换。当前所检查的逻辑没有体现新 App 启动失败后自动切回旧版本的机制。

**不能将 IAP HEX 改名为 OTA HEX 后使用，也不能假设切换模式后继续使用同一文件。** HEX 包含目标地址，OTA 还包含升级头和 CRC。其他产品应使用对应产品、芯片型号和升级模式的配套文件。

## 5. CDBUS 烧录操作

### 5.1 确认连接与文件

- 确认设备供电、工具连接通道、设备地址和通信参数。
- 先尝试读取设备信息，确认目标设备能够应答。
- 确认固件对应正确的产品和芯片型号，例如 ESP32-C3 与 ESP32-C5 不能混用。
- 准备配套升级文件。当前 `dp_esp` 工程中，IAP 使用 `dp_esp_iap.hex`，OTA 使用 `dp_esp_ota.hex`。

### 5.2 优先使用 IAP 模式 1

1. 在 CDBUS 中选中目标设备及 IAP HEX 文件。
2. 选择模式 1，按公司现行流程执行“进入 BL → 烧录 → 重启”。
3. 观察设备是否成功进入 BL；对于当前 `dp_esp`，BL 设备信息包含 `(bl)`。
4. 确认进入 BL 后，等待擦除、写入及工具提供的校验流程完成。
5. 等待设备启动，重新读取版本并检查蓝牙功能。

注意：模式编号依据公司操作记录；如界面选项内容有变化，应核对其实际动作。

### 5.3 IAP 不成功时使用 OTA 模式 4

1. 先确认设备仍能进入原 App，并能正常通信。
2. 排除连接和地址等基础问题，确认当前程序支持模式 4 对应的应用侧升级协议。
3. 换用配套 OTA HEX 文件，选择模式 4。
4. 无需先手动进入 BL，让 App 接收升级数据。
5. 等待传输完成及设备重启。当前 `dp_esp` 重启后还需由 BL 校验、搬运新程序。
6. 重新连接，读取版本并检查蓝牙功能，确认新程序已生效。

**工具显示传输结束，不等于新固件已经运行。** 以重启后的版本和功能检查作为完成依据。

### 5.4 两种模式都失败

不要只反复切换模式。应分别检查：

- 是否能够读到设备信息，连接通道和地址是否正确。
- 当前 App 是否正常运行、是否支持 OTA。
- BL 是否支持 CDBUS IAP，以及是否成功进入 BL。
- HEX 是否与产品、芯片、分区及升级模式匹配。

若 App 已损坏、OTA 不可用，同时 BL 也无法进入，应考虑通过 ESP ROM 下载方式使用乐鑫工具恢复；是否重刷 BL 和分区表，需按对应产品的固件包要求执行。

## 6. 常见提示：Not found string "(bl)", reboot...

该提示表示：工具尚未从设备信息中读到预期的 `(bl)` 标识，因此没有确认设备进入兼容的 IAP bootloader，正在尝试重启。

可能原因包括：

- 重启进入 BL 的命令没有成功执行，或设备重启后直接进入 App。
- 设备没有配套 BL，或者 BL 版本、协议及设备信息格式不兼容。
- 设备地址、波特率、连接或供电存在问题。
- 设备没有停留在升级通信阶段，或 BL 通信初始化失败。

该提示本身不能证明 HEX 损坏，也不能单独证明设备不支持 IAP。先核对设备应答和 BL 状态；如果 App 正常且明确支持应用侧升级，再尝试 OTA 模式 4。

## 7. USB 连接方式的区别

| 实际接法 | 升级路径 | 文件选择 |
|---|---|---|
| USB 转 RS-485，通过 CDBUS 连接设备 | 使用设备支持的 CDBUS 升级协议 | 按模式选择配套 IAP 或 OTA HEX |
| USB 直接接 ESP 下载接口，使用乐鑫工具 | ESP ROM 下载烧录 | 按固件包要求选择 BIN 和烧录地址 |
| 经网关、蓝牙或其他转发链路连接 | 由工具和设备协议决定 | 按产品说明选择配套文件 |

“插着 USB 线”不能单独决定选 IAP 还是 OTA，关键是 USB 后面连接的设备、实际通信链路和使用的升级协议。

## 8. 操作速记

> 公司 CDBUS 升级蓝牙程序：先尝试 IAP 模式 1，进入 BL 后烧录配套 IAP HEX；若无法完成 IAP，检查连接与 BL 状态。确认原 App 正常且支持 OTA 后，改用 OTA 模式 4 和配套 OTA HEX，无需先进入 BL。完成后等待重启，检查版本及蓝牙功能。

## 9. 工程依据

- `src/tools/app_bin2hex.py`：IAP、OTA HEX 的地址和封装。
- `src/bootloader_components/cd_boot_hooks/hooks.c`：OTA 校验、搬运及 BL 运行流程。
- `src/bootloader_components/cd_boot_hooks/comm_service.c`：BL 设备信息中的 `(bl)` 标识。
- `src/main/usr/comm_service.c`：App 发起重启并请求停留在 BL 的处理。
- `Readme.md`：RS-485 IAP、BLE/UDP OTA 与 USB 调试口升级入口。
- 公司操作记录：CDBUS 优先使用 IAP 模式 1，必要时尝试 OTA 模式 4；模式编号未通过工具源码独立验证。
