# 第21课：git blame 查看行历史

## 本课目标

理解某一行代码或文档最后由哪个提交修改，并能进一步定位对应的提交说明。

## 核心概念

`git blame` 会为文件中的每一行标出最后一次修改它的提交、作者和日期。

它回答的是：

```text
这一行最后是谁、在哪个提交中修改的？
```

它不是用来判断谁“应该负责”或谁“写错了代码”。重构、复制、批量格式化也可能改变 blame 结果。

## 常用命令

```powershell
git blame -- README.md
```

- 作用：查看整个文件每一行的最后修改来源。
- `--`：分隔 Git 参数和文件路径。
- 改变范围：只读取本地仓库，不改变工作区、暂存区、本地提交历史或远程仓库。
- 输出：每行前通常包含提交短哈希、作者、日期、行号和行内容。

```powershell
git blame -L 1,12 -- README.md
```

- `-L 1,12`：只查看第 1 到第 12 行。
- 适合文件较大时缩小输出范围。

```powershell
git show <commit-id>
```

- 作用：查看 blame 找到的提交具体修改了什么，以及提交说明。
- `<commit-id>`：替换为 blame 输出中的提交哈希。

## 如何排查结果

- 文件路径错误：先确认文件名和相对路径。
- 行号超出文件范围：缩小 `-L` 的范围。
- 显示的是格式化提交：继续用 `git show` 查看该提交，必要时结合文件历史判断。
- 想看更早的修改：不能只依赖当前 blame，应对该提交的父提交继续检查，或查看文件历史。

## VS Code 中查看

- 打开目标文件后，可以使用文件的 Timeline 查看该文件相关提交历史。
- 安装 GitLens 等 Git 扩展后，通常可以在代码行旁显示作者、提交和修改时间，也可以点击行信息查看提交详情。
- VS Code 的界面只是对 Git 历史信息的可视化；底层依据仍然是提交历史。

## 与其他命令的区别

| 命令 | 主要问题 |
|---|---|
| `git log -- README.md` | 这个文件经历过哪些提交 |
| `git blame README.md` | 每一行最后由哪个提交修改 |
| `git show <commit>` | 某个提交具体改了什么 |
