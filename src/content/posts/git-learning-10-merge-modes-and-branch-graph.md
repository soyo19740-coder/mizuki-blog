## 本课目标

通过真实开源仓库 `github/gitignore` 的实际提交图，理解分支为什么会分叉、普通合并提交是什么，以及它和 fast-forward 合并的关系。

本课已完成“分支图与普通合并”的观察和解释；`--no-ff` 与 squash 的动手练习留待后续继续。

当前分支为 `main`，本地 `main` 比 `origin/main` 领先多个本地练习提交。相关本地分支包括：

## 使用的命令

### `git status`

作用：检查当前分支、工作区、暂存区和与远程跟踪分支的关系。

影响区域：只读取工作区、暂存区、本地仓库和远程跟踪信息；不改变任何区域。

本课发现：`README.md` 有一条未暂存修改，不能直接假定工作区干净。

### `git branch --show-current`

作用：仅输出当前所在的本地分支名。

影响区域：只读取本地仓库；不改变任何区域。

本课输出：`main`。

### `git branch -vv`

作用：列出本地分支、每个分支指向的最近提交，以及有配置时的远程跟踪关系。

关键参数：`-v` 显示最近提交；第二个 `v` 额外显示跟踪关系。

影响区域：只读取本地仓库；不改变任何区域。

### `git log --oneline --graph --decorate --all -n 15`

作用：以简洁提交信息显示最近提交图，用于判断分支是直线关系还是已经分叉。

关键参数：

- `--oneline`：每个提交只显示短哈希和主题。
- `--graph`：用 ASCII 线画出父子提交关系。
- `--decorate`：显示 `HEAD`、本地分支和远程跟踪分支标签。
- `--all`：包含所有本地分支和远程跟踪分支。
- `-n 15`：最多显示 15 条提交。

影响区域：只读取本地仓库；不改变任何区域。

### `git diff --staged`

作用：比较暂存区与最近一次提交，检查已暂存但未提交的内容。

关键参数：`--staged` 等价于 `--cached`。

影响区域：只读取暂存区与本地仓库；不改变任何区域。

本课输出为空，说明没有已暂存修改。

注意：`git diff -staged` 是错误写法。长选项必须使用两个连字符：`--staged`。

### `git diff -- README.md`

作用：只查看 `README.md` 的工作区修改。

关键参数：`--` 是“选项结束符”；它与文件名之间必须有空格。它告诉 Git 后面的 `README.md` 是路径，不是选项或提交名。

影响区域：只读取工作区和暂存区；不改变任何区域。

本课看到的变化是 README 末尾新增了一行 `aiyin`。

注意：`git diff --README.md` 是错误写法，因为 Git 会把它当作不存在的长选项。

### `git restore README.md`

作用：用暂存区版本覆盖 `README.md` 的未暂存工作区修改。

影响区域：改变工作区；不改变暂存区、本地提交历史或远程仓库。

风险：若修改没有暂存或提交，执行后通常无法从 Git 历史找回。执行前应先用 `git diff -- README.md` 确认放弃目标。

本课中用于放弃 README 末尾新增的未暂存行。

## 合并结论

### 普通合并提交

`d051a26` 的图形有两条父线，表示它有两个父提交：`dbda7a4` 和 `53a5003`。这是一条合并提交，保存了“将 aiyin 合并进 main”这一事实。

### Fast-forward merge

当目标分支自从创建功能分支后没有产生任何新提交时，Git 可以直接把目标分支指针向前移动到功能分支末端，不会新建合并提交。

### `git merge --no-ff`

即使满足 fast-forward 条件，也强制创建一个合并提交。适用于希望在历史中明确保留功能分支合并节点的团队。

### `git merge --squash`

把来源分支的文件改动汇总到当前工作区和暂存区，但默认不会创建合并提交，也不会保留来源分支提交与目标分支之间的父子关系。之后需要自行执行 `git commit`。

## 本课状态总结

- 工作区：曾有 README 的未暂存修改，已用 `git restore README.md` 放弃。
- 暂存区：本课检查时为空。
- 本地仓库：通过提交图确认已有一次真实合并提交；本课的观察命令不改变历史。
- 远程仓库：本课没有执行 fetch、pull、push 或其他远程操作。
