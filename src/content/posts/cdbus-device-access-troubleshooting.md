# cdbus 访问不到的解决办法

## 1. 适用情况与处理思路

当 cdbusgui 无法访问设备、读取寄存器显示超时，或协议列表缺少设备配置时，按以下顺序排查：

**补齐协议文件 → 核对串口、地址和接线 → 进入 BL 模式 → 修正设备波特率 → 保存并重启验证。**

如果上位机使用 115200，而设备的 `bus_cfg_baud_l`、`bus_cfg_baud_h` 分别为 2,000,000 和 20,000,000，波特率不匹配会导致无法访问。可通过 BL（BootLoader）模式恢复访问，将两项都设为 115200 并保存。

以下 BL 操作适用于支持开机短暂以 115200 通信、且设备页面提供相应 BL 入口的 dprinter 设备。其他型号应核对对应协议和启动行为。

## 2. 补齐协议配置文件

**现象：**设备协议下拉列表中没有 `dpinter.json`。

1. 取得与设备匹配的 `dpinter.json`，保留原文件名。
2. 将文件放入 **cdbusgui 的 `configs` 目录**。
3. 重启 cdbusgui。
4. 在设备配置下拉列表中选择 `dpinter.json`，打开相应设备页面。

文件必须放在程序使用的配置目录中。补齐 JSON 解决的是协议列表缺项，设备仍然超时时需继续检查通信参数。

## 3. 核对串口、设备地址与接线

### 串口设置

1. 选择实际连接转换器的 COM 口，例如 `COM11`。COM 号以本机识别结果为准。
2. 为后续 BL 恢复操作，将上位机波特率设为 **115200**。
3. 关闭串口后重新打开，并刷新页面。

### 设备地址

设备页面地址必须与目标设备一致。例如，设备的 `bus_cfg_mac` 为 `0x10` 时，对应示例地址为 `00:00:10`。实际地址应按设备配置填写。

### RS-485 接线

核对设备与转换器的 A/B 接线，并确认接触可靠。对于采用以下线色定义的线束：

| 线色 | 转换器端子 |
| --- | --- |
| 黄线 | B |
| 白线 | A |

线色定义并非通用标准，其他线束应以设备端子标识或接线说明为准。

## 4. 持续超时时，进入 BL 模式

1. 确认上位机串口已打开，波特率为 **115200**。
2. 打开使用 `dpinter.json` 的设备页面。
3. 滚动到页面最下方，选择 **进入 BL 模式**；对应模式选项选择 **模式3**。
4. 点击“开始”，程序会持续转圈并尝试进入 BL。
5. 在程序持续尝试期间，**重启板子**。
6. 板子开机约 **1 秒内以 115200 对外通信**，程序利用这个窗口进入 BL。
7. 成功进入后，转圈停止。读取设备信息和寄存器，确认已经能够访问设备。

设备信息中的 `dprinter (bl)` 标记可用于识别 BL 状态。如果仍然超时，重新核对串口、地址、A/B 接线以及设备是否支持上述启动窗口。

## 5. 将设备波特率改为 115200 并保存

进入可访问的设备寄存器页面后，按以下顺序写入：

| 寄存器 | 写入值 | 用途 |
| --- | --- | --- |
| `bus_cfg_baud_l` | `115200` | 设置第一项总线波特率 |
| `bus_cfg_baud_h` | `115200` | 设置第二项总线波特率 |
| `save_conf` | `1` | 保存修改后的配置 |

1. 将 `bus_cfg_baud_l` 和 `bus_cfg_baud_h` **两项都写为 `115200`**。
2. 再向 `save_conf` **写入 `1`**，执行保存。
3. 重启板子。
4. 上位机保持 115200，重新打开串口并刷新。
5. 读取设备信息及寄存器，确认访问正常。

仅修改输入框数值不等于完成寄存器写入；应执行页面对应的写入操作，并完成 `save_conf` 保存。

## 6. 如何确认问题已解决

- 协议列表能选择 `dpinter.json`。
- 串口号和设备地址与实际设备一致。
- 设备信息、寄存器能正常读取，不再显示超时。
- `bus_cfg_baud_l` 和 `bus_cfg_baud_h` 均为 115200。
- 已向 `save_conf` 写入 1。
- 板子重启后，上位机仍能以 115200 正常访问设备。

**以重启后仍可正常读取为完成标准。**如果只在 BL 状态下能读取，继续检查参数是否正确写入、配置是否保存，以及重启后实际使用的波特率。
