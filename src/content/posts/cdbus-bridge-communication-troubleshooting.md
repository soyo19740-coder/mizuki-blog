# CDBUS Bridge 通信排障笔记

记录日期：2026-11-25

## 1. 重点：最终解决办法

本次使用 CDBUS Bridge 连接主板，通过 CDBUS GUI 以 20 Mbps 通信。

**实测有效操作：将两位拨码开关组 S1 的第 2 位，即 S1.2，拨到 ON，通信恢复。**

S1.2 控制仲裁模式下首字节速率 `baud_l` 的默认上限，不是直接选择 20 Mbps。

| 状态 | 首字节低速上限 | GUI 设置 20 Mbps 时的典型组合 |
|---|---:|---|
| OFF | 默认 1 Mbps | 首字节 1 Mbps，后续 20 Mbps |
| ON | 默认 2 Mbps | 首字节 2 Mbps，后续 20 Mbps |

上述组合适用于默认上限配置及仲裁模式；上限允许修改。最符合本次结果的解释是：主板首字节速率为 2 Mbps，S1.2 开启后两端匹配。首字节不匹配时，即使后续速率均为 20 Mbps，也可能无法识别完整帧。

“打开 S1.2 后恢复通信”已经实测确认；主板确切的 `bus_cfg_baud_l`、`bus_cfg_baud_h` 仍需读取配置或检查固件确认。

## 2. 重点：访问不到时进入 BL

### 操作步骤

1. 将 GUI 通信波特率设置为 **115200**。
2. 关闭并重新打开串口，让新设置生效。
3. 打开对应设备页面，确认目标地址、设备配置文件正确。
4. 在 IAP 页面选择第三项：**Reboot → BL（Enter BootLoader）**。
5. 点击开始，等待识别到包含 `(bl)` 的设备信息。
6. 确认出现 **keep_in_bl succeeded**，表示已进入并保持在 BL。

**模式三只负责进入并保持 BL，不执行固件烧录。**

### GUI 实际执行流程

```text
循环读取设备信息
    ├─ 收到 APP 信息：发送“重启进入 BL”命令
    ├─ 收到带 (bl) 的信息：发送“保持 BL”命令，成功后结束
    └─ 没收到信息：继续查询
```

本地实现：`html/plugins/iap.js` 中的 `do_reboot()`、`keep_in_bl()` 和 IAP 启动流程。配置文件提供重启寄存器与保持 BL 寄存器地址。

### 为什么先设为 115200

- 可能匹配主板 BL 或启动阶段使用的通信速率。
- 默认仲裁配置下，115200 低于 1 Mbps 和 2 Mbps 上限，可避开此前首字节速率上限不同的问题。
- GUI 未规定所有主板 BL 都使用 115200；确切速率取决于主板固件。本次操作经验不能代替固件定义。

**适用边界：模式三不是硬件强制启动。**代码需要先收到设备信息回复，才会判断是否发送重启进入 BL 的命令。APP 完全无响应、地址错误或线路不通时，它只会继续查询；可能需要配合主板复位或主板自身的硬件启动方式。

桥上的 **S1.1 让桥自身进入 Bootloader**，不能代替主板进入 BL。BL 中可访问的功能由 BL 固件决定，不等于 APP 的所有寄存器功能都能使用。

## 3. 本次排障过程与证据

| 操作或现象 | 可以得出的结论 |
|---|---|
| 接主板后，一根线接近 3 V、呈三角形；另一根只变化几百 mV | 波形需要核对测量设置、速率和总线状态，不能直接判断硬件损坏 |
| 主板仍连接时，改在桥端测量也类似 | 两端在同一总线上，不能据此排除主板影响 |
| 拆下主板，桥单独发送正常，测到约 3.3 V 的摆幅或差值 | 桥具有正常输出能力，但空载幅度不等于带载幅度 |
| 打开 S1.2 后，20 Mbps 通信成功 | 首字节速率配置匹配是本次关键因素 |

早期曾怀疑主板负载、收发器供电、DE 控制争用、保护器件钳位。这些是排查假设，**没有被证实为本次根因**。此前三角波和不对称的具体成因尚未单独验证，不能认为 S1.2 的改变已经解释全部模拟波形细节。

## 4. 示波器操作：接线、设置与抓包

### 4.1 正确接线

普通台式示波器两个通道地夹通常内部相连，并连接保护地。确认通信侧 GND 可以与示波器保护地连接；隔离或浮地系统应使用合适的差分探头，不要拆除示波器保护地。

```text
CH1 探头尖端 → A
CH2 探头尖端 → B
两个探头地夹 → 同一个通信侧 GND
数学运算     → CH1 − CH2
```

**不能把两个地夹分别接 A、B，也不能把地夹接在 B 上当作差分测量。**这可能短接总线，使某根线被拉住。

A/B 为通信线；桥的电源“+、−”不是另一组差分通信线。接线前核对丝印和版本。

### 4.2 基础设置

| 项目 | 建议设置 |
|---|---|
| 探头 | 两通道均使用 ×10，示波器倍率设置与探头一致 |
| 输入阻抗 | 1 MΩ，避免误用 50 Ω 输入加载总线 |
| 耦合 | DC，保留真实直流电平 |
| 接地 | 尽可能短，优先用地弹簧，减少长地线引起的振铃 |
| 电压档位 | 先用约 1 V/格观察，再按实际幅度调整 |
| 带宽 | 检查是否开启带宽限制；测量带宽需足够反映高速边沿 |
| 采样率 | 保证每个 50 ns 数据位有多个采样点；仪器允许时可先用 1 GSa/s 或更高 |
| 采集模式 | 先用普通采样；避免平均功能把非重复数据波形抹平 |

### 4.3 实际抓取步骤

1. 确认桥和主板供电、A/B 接线、通信侧参考地正确。
2. 设置 GUI 的目标速率，重新打开串口。
3. 示波器先选较长记录窗口，例如 10～100 μs/格，查找整个请求包；无触发时适当扩大窗口。
4. 选择边沿触发，触发源 CH1 或仪器支持的差分通道，电平放在对应波形高低电平之间。
5. 按 **Single（单次）**，让示波器等待触发。
6. 在 GUI 点击 **读取设备信息**，触发实际通信。
7. 找到请求包后放大：观察 20 Mbps 数据位可用约 **20～100 ns/格**；观察 2 Mbps 首字节可用约 **200～500 ns/格**。
8. 同时保存 CH1、CH2 和 CH1−CH2，截图保留电压刻度、时间刻度、采样率、探头倍率。

如果单次触发没抓到，先用 Auto/Normal 查找合适的触发电平，或切换上升沿、下降沿后重试。请求与回复间隔由固件决定，必要时增加记录长度或调整触发位置。

**仅打开串口不会主动发送握手请求。**主页 Online 主要表示电脑 COM 口打开，并不证明主板应答。打开设备窗口会自动读取信息，也可手动点击读取信息产生请求。

### 4.4 位宽速查

| 速率 | 每位时间 | 8N1 连续一个字节所需时间 |
|---|---:|---:|
| 115200 | 约 8.68 μs | 约 86.8 μs |
| 1 Mbps | 1 μs | 10 μs |
| 2 Mbps | 500 ns | 5 μs |
| 20 Mbps | 50 ns | 500 ns |

8N1 一字节包含起始位、8 位数据和停止位，共 10 位。表中不含帧间间隔、仲裁及协议开销。

**验证 S1.2 时，应分开看首字节和后续字节。**默认情况下首字节可能从 1 μs/位变成 500 ns/位，后续仍是 50 ns/位。若混合速率，固定为 20 Mbps 的 UART 解码器可能误解首字节；应分段解码或先直接量位宽。

### 4.5 波形判断

```text
时间 →        桥发送请求           主板处理         主板回复
总线：空闲 ──[请求数据脉冲]───────────────[回复数据脉冲]── 空闲
```

- 优先看差分电压 A−B 是否随数据改变极性，不能只凭一根线对地约 3 V 判断正常。
- A/B 通常反向变化，但实际单端幅度不必完全对称。
- 空闲偏置与电源、终端和上下拉配置有关，不规定必须某根线为固定 3.3 V。
- 20 Mbps 的位宽只有 50 ns，探头电容、带宽不足、长接地线或大负载都可能让边沿变圆或呈三角形。
- 数据速率不匹配通常导致解析失败；并不必然导致模拟波形失真。

### 4.6 对照排查

1. 保持探头设置不变，记录主板连接时的波形。
2. 断电后断开主板 A/B，再给桥上电并重复发送相同请求。
3. 桥单独正常、接主板异常：检查主板供电、收发器型号及速率能力、DE/RE、保护器件、线缆和终端。
4. 桥单独也异常：检查探头接地、输入阻抗、桥模式与硬件。
5. 每次只改变一个变量；比较时记录有无终端，空载和带载幅度不可直接等同。

检查 DE/RE 必须以收发器或控制器手册为准；不要在 MCU 正驱动引脚时强行短接到地。确认发送器在接收请求阶段是否正确释放总线。

## 5. 桥接口及拨码速查

以下来自官方 Bridge HS 文档，须先核对硬件版本。

| 标记 | 功能 |
|---|---|
| A、B | RS-485 差分通信端 |
| +、− | 通常为电源正极和 GND，具体核对版本资料 |
| S1.1 | 强制桥自身进入 Bootloader |
| S1.2 | 仲裁模式 `baud_l` 默认上限：OFF 1 Mbps；ON 2 Mbps |
| S2.1 | 启用上拉电阻 |
| S2.2 | 启用终端电阻 |
| S2.3 | 启用下拉电阻 |
| S2.4，v6.2 及以后 | 与 S2.3 同时开启时，将 B 偏置到 1.65 V，使 A 可用于 TTL 单线串口 |
| S2.5，v6.2 及以后 | 启用 5 V 输出 |
| S2.4，早于 v6.2 | 启用 5 V 输出，不能套用新版本 TTL 功能定义 |

使用外部供电时，按官方要求关闭桥的 5 V 输出。输出关闭时，“+”对“−”为 0 V 可能正常，与 20 Mbps 无直接关系。

终端通常设在总线两个物理末端，避免重复并联；若两端各为 120 Ω，断电后整条总线 A—B 常见约 60 Ω，但偏置和其他板上电路会影响测量。20 Mbps 下还需关注线缆、支路长度和器件带宽。

## 6. 后续复用的操作顺序

1. **正常高速通信：确认 S1.2 为 ON，GUI 设置 20 Mbps，并核对主板首字节速率。**
2. **访问 BL：先设 115200，重新打开串口，选择 IAP 第三项，确认 `(bl)` 和 keep_in_bl succeeded。**
3. 通信不通时先抓真实请求，核对位宽；再检查地址、配置、主板状态。
4. 波形异常时检查探头接法，再用桥单独发送与接主板发送对照定位，避免直接认定硬件损坏。
